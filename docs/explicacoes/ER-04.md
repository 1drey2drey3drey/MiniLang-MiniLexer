# ER-04 — Número em notação científica

## 1. O que esta ER reconhece

A ER-04 reconhece números na forma de **notação científica**.

A estrutura geral é:

```text
mantissa + e/E + expoente
```

A mantissa pode ser:

```text
0
ou
inteiro iniciado em 1-9, com dígitos adicionais
```

Opcionalmente, a mantissa pode possuir uma parte decimal:

```text
. + um ou mais dígitos
```

Depois vem obrigatoriamente:

```text
e
ou
E
```

O expoente pode possuir sinal opcional:

```text
+
-
```

e precisa terminar em pelo menos um dígito.

Exemplos válidos:

```text
0e0
9E9
1e10
1.5e3
12.25E-2
2026.75e+10
```

## 2. Definições auxiliares

```text
N = {1,...,9}
D = {0,...,9}
P = {.}
```

Para a construção formal, `e`, `E`, `+` e `-` são símbolos literais.

## 3. Linguagem reconhecida

A expressão formal definitiva é:

```text
(0 | ND*) (PDD* | ε) (e | E) (+ | - | ε) DD*
```

A decomposição é:

```text
parte inteira válida
+
parte decimal opcional
+
e ou E obrigatório
+
sinal opcional
+
expoente numérico obrigatório
```

A palavra **opcional** aparece somente na parte decimal e no sinal do expoente. O marcador `e/E` e os dígitos do expoente são obrigatórios.

## 4. Expressão Regular formal

```text
(0 | ND*) (PDD* | ε) (e | E) (+ | - | ε) DD*
```

## 4. Sintaxe exata em Python

```python
REGEX_ER04 = r"(0|[1-9][0-9]*)(\.[0-9]+)?[eE][+-]?[0-9]+"
```

A validação de cadeia inteira usa:

```python
re.fullmatch(REGEX_ER04, cadeia)
```

## 5. Tradução formal → Python

| Formal | Python |
|---|---|
| `0` | `0` |
| `N` | `[1-9]` |
| `D` | `[0-9]` |
| `P` | `\.` |
| `PDD*` | `\.[0-9]+` |
| `PDD* | ε` | `(\.[0-9]+)?` |
| `e | E` | `[eE]` |
| `+ | - | ε` | `[+-]?` |
| `DD*` | `[0-9]+` |
| união | `|` |
| concatenação | justaposição |
| agrupamento | `( ... )` |

## 6. A ideia central da ER-04

Para estudar essa ER, não tente memorizar o padrão inteiro de uma vez.

Memorize os cinco blocos:

```text
B1 = parte inteira
B2 = decimal opcional
B3 = e/E obrigatório
B4 = sinal opcional
B5 = expoente obrigatório
```

Em símbolos:

```text
B1 B2 B3 B4 B5
```

Onde:

```text
B1 = (0|[1-9][0-9]*)
B2 = (\.[0-9]+)?
B3 = [eE]
B4 = [+-]?
B5 = [0-9]+
```

## 7. Explicação dos operadores

### União `|`

A parte inteira usa:

```text
0 | ND*
```

O expoente usa:

```text
+ | - | ε
```

E o marcador científico usa:

```text
e | E
```

### Kleene `*`

Na forma formal:

```text
D*
```

permite que a parte inteira iniciada por `N` continue com quantos dígitos forem necessários.

### Opcional `?`

O grupo:

```text
(\.[0-9]+)?
```

permite duas possibilidades:

```text
sem parte decimal
ou
com parte decimal
```

O grupo:

```text
[+-]?
```

permite:

```text
sem sinal
+
-
```

### Mais `+`

```text
[0-9]+
```

exige pelo menos um dígito.

Isso é usado tanto na fração quanto no expoente.

## 8. Por que `1e10` é válido?

Dividindo:

```text
1 | e | 10
```

Temos:

```text
1      → parte inteira
(e)    → marcador científico
10     → expoente
```

Como a fração é opcional, ela pode ser omitida.

## 9. Por que `1.5e3` é válido?

A cadeia é dividida em:

```text
1 | .5 | e | 3
```

A parte decimal opcional é usada porque existe `.5`.

O expoente `3` possui um dígito, satisfazendo `[0-9]+`.

## 10. Por que `1.5E-3` é válido?

A estrutura é:

```text
1
.
5
E
-
3
```

O `[eE]` aceita `E`.

`[+-]?` aceita `-`.

`[0-9]+` aceita `3`.

## 11. Casos aceitos

| Cadeia | Decomposição |
|---|---|
| `0e0` | `0 + e + 0` |
| `9E9` | `9 + E + 9` |
| `1e10` | `1 + e + 10` |
| `1.5e3` | `1 + .5 + e + 3` |
| `12.25E-2` | `12 + .25 + E + - + 2` |
| `2026.75e+10` | `2026 + .75 + e + + + 10` |

## 12. Casos rejeitados

### `e10`

Não existe parte inteira antes do `e`.

### `1e`

Existe marcador científico, mas o expoente não possui dígito.

### `1.e3`

A parte decimal foi iniciada, mas não possui nenhum dígito depois do ponto.

### `.5e2`

Falta a parte inteira antes do ponto.

### `01e2`

A parte inteira tem zero à esquerda.

### `1.2e3.4`

O expoente deveria ser formado apenas por dígitos; o segundo ponto não é permitido.

## 13. Casos-limite

```text
0e0     → menor forma científica válida
9E9     → marcador em maiúsculo
1e+0    → sinal positivo explícito
1e-0    → sinal negativo explícito
00e1    → zero à esquerda, inválido
1.e1    → decimal incompleto, inválido
1.2e    → expoente ausente, inválido
```

Os pares mais instrutivos são:

```text
1e0   × 1e
1.0e0 × 1.e0
1e+0  × 1e+
```

## 14. AFNε da ER-04

```text
Inicial: q0
Final:   q39
Estados: 42
Transições: 52
Transições ε: 40
Transições rotuladas: 12
```

A construção atual é a tabela canônica congelada do projeto.

## 15. Bloco da parte inteira

O início do autômato é o mesmo princípio usado nas ER-02 e ER-03:

```text
q0 --ε--> q2
q2 --0--> q3
q3 --ε--> q1
```

ou:

```text
q0 --ε--> q4
q4 --N--> q5
...
```

Isso implementa:

```text
0 | ND*
```

## 16. Bloco decimal opcional

A fração é construída como um caminho que pode ou não ser escolhido:

```text
q1 --ε--> q10
```

A partir de `q10`, existem duas alternativas:

```text
q10 --ε--> q12
```

para entrar na parte decimal, ou:

```text
q10 --ε--> q20
```

para ignorá-la.

O caminho decimal é:

```text
q12 --.--> q13
q13 --ε--> q14
q14 --D--> q15
q15 --ε--> q16
q16 --ε--> q18
q16 --ε--> q17
q18 --D--> q19
q19 --ε--> q18
q19 --ε--> q17
```

Ele implementa a parte decimal obrigatoriamente com pelo menos um dígito quando escolhido.

## 17. Bloco alternativo de fechamento da fração

O restante do bloco:

```text
q17 --ε--> q11
q20 --ε--> q21
q21 --ε--> q11
```

serve para reunir os caminhos:

```text
com decimal
sem decimal
```

antes do marcador `e/E`.

## 18. Bloco `e | E`

```text
q11 --ε--> q22
q22 --ε--> q24
q24 --e--> q25
q25 --ε--> q23
```

ou:

```text
q22 --ε--> q26
q26 --E--> q27
q27 --ε--> q23
```

Isso representa:

```text
e | E
```

A estrutura usa uma união por ε: o autômato escolhe entre a transição `e` e a transição `E`.

## 19. Bloco do sinal opcional

Depois do marcador científico:

```text
q23 --ε--> q28
```

Em `q28`, há três escolhas:

```text
q28 --ε--> q30 --+--> q31 --ε--> q29
q28 --ε--> q32 -----> q33 --ε--> q29
q28 --ε--> q34 --ε--> q35 --ε--> q29
```

Funcionalmente:

```text
+
-
nenhum sinal
```

Isso é exatamente:

```text
(+ | - | ε)
```

## 20. Bloco do expoente obrigatório

Finalmente:

```text
q29 --ε--> q36
q36 --D--> q37
q37 --ε--> q38
```

Depois, `q38` permite:

```text
q38 --ε--> q39
```

ou continuar para mais dígitos:

```text
q38 --ε--> q40
q40 --D--> q41
q41 --ε--> q40
q41 --ε--> q39
```

Essa estrutura implementa:

```text
DD*
```

O primeiro `D` é obrigatório; os seguintes são opcionais/repetíveis.

## 21. Exemplo de caminho de aceitação: `1.5e-3`

Uma execução possível:

```text
q0 --ε--> q4
q4 --1--> q5
q5 --ε--> q6
q6 --ε--> q7
q7 --ε--> q1
q1 --ε--> q10
q10 --ε--> q12
q12 --.--> q13
q13 --ε--> q14
q14 --5--> q15
q15 --ε--> q16
q16 --ε--> q17
q17 --ε--> q11
q11 --ε--> q22
q22 --ε--> q24
q24 --e--> q25
q25 --ε--> q23
q23 --ε--> q28
q28 --ε--> q32
q32 ----> q33   (consumo de '-')
q33 --ε--> q29
q29 --ε--> q36
q36 --3--> q37
q37 --ε--> q38
q38 --ε--> q39
```

O último estado é `q39`, que é final.

## 22. Exemplo de rejeição: `1e`

A parte inteira `1` é válida.

O marcador `e` também é válido.

O problema aparece no final:

```text
expoente = vazio
```

Como a ER exige:

```text
D+
```

não existe caminho de aceitação depois de consumir `e`.

## 23. Exemplo de rejeição: `1.e3`

A parte inteira `1` é válida.

O ponto é lido, mas depois dele é necessário pelo menos um dígito.

A cadeia fornece imediatamente `e`.

Logo o grupo decimal escolhido fica incompleto.

## 24. Relação com o MiniLexer

A ER-04 é usada dentro de:

```python
_scan_number_or_time()
```

Quando o lexer encontra:

```text
e
E
```

após um candidato numérico, ele continua consumindo o possível sinal e os dígitos do expoente.

Depois monta o candidato completo e usa:

```python
re.fullmatch(REGEX_ER04, candidate)
```

Se a forma científica não estiver completa, o lexer lança `LexicalError` em vez de aceitar um prefixo incompleto.

Por exemplo:

```text
1.5e
```

não deve virar:

```text
DECIMAL("1.5")
IDENTIFIER("e")
```

porque o `e` sinaliza um candidato científico que precisa ser validado como um todo.

## 26. Limitações

A ER-04 verifica o **formato lexical** da notação científica.

Ela não calcula:

```text
1e10
```

nem determina o valor numérico, overflow, underflow ou precisão.

Esses assuntos pertencem a etapas posteriores.

## 27. Checklist mental

```text
1. A parte inteira é obrigatória.
2. A fração é opcional.
3. e/E é obrigatório.
4. O sinal é opcional.
5. O expoente é obrigatório e tem pelo menos um dígito.
6. 1e0 é válido.
7. 1e é inválido.
8. 1.e0 é inválido.
9. 01e0 é inválido.
```

Pergunta típica:

> Por que `1e` não pode ser um científico parcialmente válido?

Resposta essencial:

> Porque o bloco final da expressão é `DD*`, equivalente a `[0-9]+`, portanto pelo menos um dígito do expoente é obrigatório.

### Como ler esta tabela

Cada linha representa **uma transição agrupada da construção canônica**. Quando o símbolo é uma classe como `L`, `N`, `D` ou `C`, a implementação Python expande essa classe internamente para seus símbolos individuais. Isso não cria um novo AFN; é a mesma transição agrupada representada de forma mais detalhada para a simulação computacional.

Nas transições marcadas como `ε`, nenhum caractere da cadeia é consumido. Elas somente mudam o conjunto de estados possíveis. Nas transições rotuladas, um símbolo da entrada precisa ser consumido.
