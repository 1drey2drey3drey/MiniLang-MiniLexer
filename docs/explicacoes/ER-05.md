# ER-05 — Literal de string

## 1. O que esta ER reconhece

A ER-05 reconhece **strings entre aspas duplas**.

A estrutura é:

```text
" conteúdo "
```

O conteúdo pode possuir zero ou mais símbolos pertencentes à classe `C` da MiniLang.

A string vazia é válida:

```text
""
```

Na primeira versão do projeto, não existem escapes.

Consequentemente, os seguintes caracteres não pertencem ao conteúdo permitido:

```text
"
\
tabulação
quebra de linha
```

## 2. Alfabeto do conteúdo

Definimos:

```text
L = letras
D = dígitos
```

e:

```text
C = L ∪ D ∪ {espaço, _, ., ,, !, ?, :, ;, +, -, *, /, =, <, >}
```

O alfabeto da string é:

```text
Σ_STR = C ∪ {"}
```

A aspa dupla faz parte do alfabeto da expressão porque delimita a string, mas **não pertence a `C`**. Isso impede aspas internas sem mecanismo de escape.

## 3. Linguagem reconhecida

Formalmente:

```text
L_STR = { " x " | x ∈ C* }
```

A expressão formal pode ser escrita como:

```text
" C* "
```

## 4. Expressão Regular formal

```text
" C* "
```

## 5. Sintaxe exata em Python

```python
REGEX_ER05 = r'"[A-Za-z0-9 _.,!?;:+*/=<>-]*"'
```

A correspondência completa usa:

```python
re.fullmatch(REGEX_ER05, cadeia)
```

## 6. Tradução formal → Python

| Formal | Python |
|---|---|
| `C` | `[A-Za-z0-9 _.,!?;:+*/=<>-]` |
| `C*` | `[A-Za-z0-9 _.,!?;:+*/=<>-]*` |
| aspas literais | `"` |
| `*` | `*` |

A parte mais importante é o `*`:

```text
C*
```

permite **zero ou mais** símbolos.

Isso explica diretamente por que `""` é válida.

## 7. Por que as aspas não pertencem a `C`?

Porque elas têm função estrutural:

```text
" → início
C* → conteúdo
" → fim
```

Se `"` também pertencesse a `C`, não haveria uma forma simples de distinguir a aspa final de uma aspa pertencente ao conteúdo.

Para a primeira versão do projeto, adotamos a decisão mais simples: **não existem escapes**.

## 8. Explicação dos operadores

### Concatenação

A forma:

```text
" C* "
```

significa:

```text
aspa inicial
seguida do conteúdo
seguida da aspa final
```

### Kleene `*`

```text
C*
```

aceita:

```text
ε
C
CC
CCC
...
```

Portanto, no interior da string podemos ter nenhum, um ou muitos caracteres.

### Classe finita

```text
[A-Za-z0-9 _.,!?;:+*/=<>-]
```

é a representação computacional de um conjunto finito de símbolos permitidos.

## 9. Exemplos aceitos

### `""`

Não existe conteúdo entre as aspas.

Formalmente:

```text
C* = ε
```

Como `*` inclui zero repetições, a string vazia é aceita.

### `"Andrey"`

As letras de `Andrey` pertencem a `C`.

### `"abc 123"`

Letras, espaço e dígitos pertencem a `C`.

### `"a_b.c"`

`_` e `.` pertencem a `C`.

### `"hello!"`

`!` pertence a `C`.

### `"12:30"`

Dígitos e `:` pertencem a `C`.

## 10. Casos rejeitados

### `ε`

Não possui aspas delimitadoras.

### `"abc`

Existe aspa inicial, mas falta a aspa final.

### `abc"`

Existe aspa final, mas falta a inicial.

### `"a"b"`

A primeira string termina em `"` após `a`; o conteúdo restante não pertence ao mesmo literal.

### `"a\b"`

A barra invertida `\` não pertence a `C`.

### `"linha\n`

Uma quebra de linha não pertence ao conteúdo permitido e também impede a string de permanecer em uma única cadeia válida.

## 11. Casos-limite

```text
""       → válido
"a"      → válido
" "      → válido
"a+b=c"  → válido
"a\b"    → inválido
"linha\n → inválido
```

Os casos mais importantes para defesa são:

```text
""       × "a"
"a"      × "a\b"
"abc"    × "abc
```

## 12. AFNε da ER-05

```text
Inicial: q0
Final:   q7
Estados: 8
Transições: 9
Transições ε: 6
Transições rotuladas: 3
```

### 12.1 Aspa inicial

```text
q0 --"--> q1
```

A string só pode começar por aspa dupla.

### 12.2 Entrada no bloco `C*`

```text
q1 --ε--> q2
q2 --ε--> q4
q2 --ε--> q3
```

Aqui ocorre uma escolha fundamental:

```text
q2 → q4
```

entra no ciclo de conteúdo;

```text
q2 → q3
```

permite ir diretamente para a aspa final.

Essa segunda opção é justamente o que permite `""`.

### 12.3 Repetição do conteúdo

```text
q4 --C--> q5
q5 --ε--> q4
q5 --ε--> q3
```

A partir de `q4` podemos consumir um símbolo de `C`.

Depois de consumir um símbolo, `q5` pode:

```text
voltar para q4 → consumir outro C
```

ou:

```text
ir para q3 → encerrar o conteúdo
```

Isso implementa `C*`.

### 12.4 Aspa final

```text
q3 --ε--> q6
q6 --"--> q7
```

A cadeia somente é aceita quando existe a aspa final e o autômato alcança `q7`.

## 13. Exemplo de caminho de aceitação: `"a+b=c"`

Uma execução possível:

```text
q0 --"--> q1
q1 --ε--> q2
q2 --ε--> q4
q4 --a--> q5
q5 --ε--> q4
q4 --+--> q5
q5 --ε--> q4
q4 --b--> q5
q5 --ε--> q4
q4 --=--> q5
q5 --ε--> q4
q4 --c--> q5
q5 --ε--> q3
q3 --ε--> q6
q6 --"--> q7
```

O conteúdo inteiro foi consumido usando o ciclo `q4 ↔ q5` e, ao final, a aspa final leva ao estado `q7`.

## 14. Exemplo de caminho de aceitação: `""`

O caminho é ainda mais importante para estudo:

```text
q0 --"--> q1
q1 --ε--> q2
q2 --ε--> q3
q3 --ε--> q6
q6 --"--> q7
```

Nenhum símbolo de `C` foi consumido.

Isso demonstra diretamente:

```text
C* contém ε
```

## 15. Exemplo de rejeição: `"a\b"`

O início é válido:

```text
"a
```

Mas `\` não pertence a `C`.

Logo o conteúdo não pode continuar pelo estado `q4`.

No `MiniLexer`, essa situação também é tratada pelo leitor de string, que rejeita caracteres não permitidos.

## 16. Relação com o MiniLexer

O `MiniLexer` trata strings no método:

```python
_scan_string()
```

O processo é:

1. encontra `"`;
2. consome a aspa inicial;
3. lê caractere por caractere;
4. aceita somente caracteres de `STRING_CHARACTERS`;
5. ao encontrar `"`, encerra o literal;
6. se encontrar tabulação/quebra de linha/caractere proibido, lança erro;
7. se chegar ao final sem aspa, lança `string não encerrada`.

Aqui existe uma decisão importante do projeto: a regex define a linguagem que o conteúdo pode ter, enquanto `_scan_string()` executa uma leitura controlada para produzir uma mensagem de erro clara e preservar linha/coluna.

## 19. Limitações

A primeira versão não possui escapes.

Portanto não é possível representar diretamente conteúdos como:

```text
"ele disse \"oi\""
```

nem barras invertidas como conteúdo normal.

Também não há diferenciação entre strings de tipos diferentes, porque isso pertence ao nível semântico, não lexical.

## 20. Checklist mental

```text
1. Sempre começa com ".
2. Sempre termina com ".
3. Conteúdo = C*.
4. C* pode ser ε.
5. Portanto "" é válido.
6. " não pertence a C.
7. \ não pertence a C.
8. quebra de linha não pertence a C.
```

Pergunta típica:

> Por que a string vazia é aceita?

Resposta essencial:

> Porque o conteúdo é `C*`, e o fechamento de Kleene permite zero ocorrências de `C`.

| 8 | `q6` | `"` | `q7` | rotulada |
| 9 | `q3` | `ε` | `q6` | ε |

### Como ler esta tabela

Cada linha representa **uma transição agrupada da construção canônica**. Quando o símbolo é uma classe como `L`, `N`, `D` ou `C`, a implementação Python expande essa classe internamente para seus símbolos individuais. Isso não cria um novo AFN; é a mesma transição agrupada representada de forma mais detalhada para a simulação computacional.

Nas transições marcadas como `ε`, nenhum caractere da cadeia é consumido. Elas somente mudam o conjunto de estados possíveis. Nas transições rotuladas, um símbolo da entrada precisa ser consumido.
