# ER-03 — Número decimal

## 1. O que esta ER reconhece

A ER-03 reconhece números decimais com as regras:

- a parte inteira pode ser `0`; ou começar em `1` até `9` e continuar com dígitos;
- obrigatoriamente existe um ponto `.`;
- depois do ponto existe **pelo menos um dígito**;
- não são aceitos zeros à esquerda na parte inteira;
- não são aceitos decimais sem dígito após o ponto;
- não são aceitos números que começam diretamente com `.`.

Exemplos válidos:

```text
0.5
0.50
1.5
9.5
10.25
2026.75
```

Exemplos inválidos:

```text
.5
5.
00.5
01.5
1.2.3
-9.5
```

## 2. Definições

```text
N = {1,...,9}
D = {0,...,9}
P = {.}
```

`P` representa o ponto decimal.

## 3. Linguagem reconhecida

A forma formal é:

```text
(0 | N D*) P D D*
```

A decomposição é:

```text
parte inteira válida
+
ponto
+
pelo menos um dígito
+
zero ou mais dígitos adicionais
```

## 4. Expressão Regular formal

```text
(0|ND*)PDD*
```

## 5. Sintaxe exata em Python

```python
REGEX_ER03 = r"(0|[1-9][0-9]*)\.[0-9]+"
```

Correspondência completa:

```python
re.fullmatch(REGEX_ER03, cadeia)
```

## 6. Tradução formal → Python

| Formal | Python |
|---|---|
| `0` | `0` |
| `N` | `[1-9]` |
| `D` | `[0-9]` |
| `P` | `\.` |
| `D*` | `[0-9]*` |
| `DD*` | `[0-9]+` |
| união | `|` |
| agrupamento | `( ... )` |

### Por que o ponto aparece como `\.`?

Em regex computacional, `.` normalmente possui significado especial. Para representar o caractere ponto literalmente, o código utiliza:

```text
\.
```

Ou seja, o `\` remove o significado especial do ponto e faz com que ele seja tratado como literal.

## 7. Explicação dos operadores

### União

```text
0 | ND*
```

A parte inteira pode ser:

- exatamente `0`;
- ou começar em `1-9` e continuar com zero ou mais dígitos.

### Fecho de Kleene

```text
D*
```

permite zero ou mais dígitos após o primeiro dígito não nulo da parte inteira.

### Concatenação

```text
(0|ND*) P D D*
```

significa colocar os blocos em sequência.

### `+` da sintaxe Python

```text
[0-9]+
```

é equivalente a:

```text
DD*
```

porque significa uma ou mais ocorrências de `D`.

## 8. Por que `0.5` é válido?

A parte inteira usa a alternativa `0`:

```text
0
```

Depois:

```text
.
```

E finalmente:

```text
5
```

Portanto:

```text
0 . 5
```

satisfaz a expressão.

## 9. Por que `00.5` é inválido?

A primeira alternativa `0` consegue consumir somente o primeiro `0`.

Depois sobra:

```text
0.5
```

A alternativa `ND*` não pode começar porque o primeiro símbolo também é `0`.

Como o código usa `fullmatch`, não adianta uma parte da cadeia parecer válida.

## 10. Por que `.5` é inválido?

A ER começa com uma **parte inteira válida**.

Logo o primeiro símbolo precisa ser `0` ou `1-9`.

Como a cadeia começa com `.`, não existe caminho válido.

## 11. Por que `5.` é inválido?

A parte inteira `5` é válida.

O ponto também é válido.

Mas depois do ponto existe:

```text
D+
```

ou seja, pelo menos um dígito.

Como a cadeia acabou, o requisito não é satisfeito.

## 12. Casos aceitos

| Cadeia | Estrutura |
|---|---|
| `0.5` | `0 . 5` |
| `0.50` | `0 . 50` |
| `1.5` | `1 . 5` |
| `9.5` | `9 . 5` |
| `10.25` | `10 . 25` |
| `2026.75` | `2026 . 75` |

## 13. Casos rejeitados

| Cadeia | Motivo |
|---|---|
| `00.5` | zero à esquerda |
| `01.5` | zero à esquerda |
| `.5` | falta parte inteira |
| `5.` | falta dígito após ponto |
| `1.2.3` | possui dois pontos |
| `-9.5` | sinal negativo não pertence à ER-03 |

## 14. Casos-limite

```text
0.5   → válido
0.50  → válido
.5    → inválido
5.    → inválido
00.5  → inválido
```

Os pares mais importantes para explicar são:

```text
0.5  ×  .5
5.   ×  5.0
0.5  ×  00.5
```

## 15. AFNε da ER-03

```text
Inicial: q0
Final:   q17
Estados: 18
Transições: 22
Transições ε: 16
Transições rotuladas: 6
```

A construção atual é a referência congelada do projeto e é validada pelo teste estrutural.

### 15.1 Parte inteira `0 | ND*`

```text
q0 --ε--> q2
q2 --0--> q3
q3 --ε--> q1
```

Esse caminho representa a alternativa do inteiro exatamente igual a `0`.

A outra alternativa é:

```text
q0 --ε--> q4
q4 --N--> q5
q5 --ε--> q6
q6 --ε--> q8
q6 --ε--> q7
q8 --D--> q9
q9 --ε--> q8
q9 --ε--> q7
q7 --ε--> q1
```

Aqui:

- `q4 → q5` consome o primeiro dígito não nulo;
- `q8 → q9` consome um dígito adicional;
- `q9 → q8` permite repetição;
- `q9 → q7` permite sair do ciclo.

### 15.2 Ponto decimal

```text
q1 --ε--> q10
q10 --.--> q11
```

Esse bloco força a existência de um ponto literal.

### 15.3 Parte fracionária

```text
q11 --ε--> q12
q12 --D--> q13
q13 --ε--> q14
q14 --ε--> q16
q14 --ε--> q17
q16 --D--> q17
q13 --ε--> q14
```

A tabela é a construção congelada usada pelo simulador. O significado funcional é:

1. chegar ao ponto;
2. consumir pelo menos um dígito;
3. permitir continuidade com outros dígitos;
4. chegar ao estado final `q17` somente após consumir a parte necessária.

## 16. Exemplo de caminho de aceitação: `12.50`

Uma execução possível no AFNε atual é:

```text
q0 --ε--> q4
q4 --1--> q5
q5 --ε--> q6
q6 --ε--> q8
q8 --2--> q9
q9 --ε--> q7
q7 --ε--> q1
q1 --ε--> q10
q10 --.--> q11
q11 --ε--> q12
q12 --5--> q13
q13 --ε--> q14
q14 --ε--> q16
q16 --0--> q17
```

Ao final, a cadeia foi inteira consumida e o autômato está em `q17`.

## 17. Exemplo de rejeição: `1.`

A parte inteira é válida:

```text
1
```

O ponto também é consumido:

```text
.
```

Mas a etapa seguinte exige um dígito da parte fracionária.

Como a cadeia acabou, não existe transição rotulada adequada para concluir a aceitação.

## 18. Exemplo de rejeição: `09.5`

O primeiro `0` pode usar somente a alternativa literal `0`, mas sobra `9.5`.

A alternativa `ND*` não pode começar por `0`.

Logo a parte inteira já é inválida antes mesmo de considerar o ponto.

## 19. Relação com o MiniLexer

A ER-03 participa do método:

```python
_scan_number_or_time()
```

Quando existe um ponto depois da sequência de dígitos, o lexer tenta formar uma candidata decimal.

Exemplo:

```text
12.50
```

A candidata inteira é validada pela ER-03.

Se a candidata for inválida, o lexer produz erro em vez de decompor incorretamente o texto em tokens menores.

Exemplo crítico:

```text
1.2.3
```

não deve ser transformado silenciosamente em algo como:

```text
DECIMAL("1.2")
.
INTEGER("3")
```

O tratamento do projeto considera o formato numérico contaminado e o rejeita.

## 22. Limitações

A ER-03 verifica apenas o **formato lexical** do decimal.

Ela não verifica:

- valor numérico dentro de um intervalo;
- número de casas decimais permitido por alguma regra de negócio;
- precisão de ponto flutuante;
- operações matemáticas.

## 23. Checklist mental

```text
1. Primeiro vem uma parte inteira válida.
2. Essa parte pode ser exatamente 0.
3. Se não for 0, começa em 1-9.
4. Depois vem obrigatoriamente '.'
5. Depois do ponto preciso de pelo menos um dígito.
6. Portanto 0.5 é válido.
7. .5 é inválido.
8. 5. é inválido.
9. 00.5 é inválido.
```

Pergunta típica:

> Por que `5.` não é aceito?

Resposta essencial:

> Porque a parte fracionária é `D+`; o ponto precisa ser seguido por pelo menos um dígito.

### Como ler esta tabela

Cada linha representa **uma transição agrupada da construção canônica**. Quando o símbolo é uma classe como `L`, `N`, `D` ou `C`, a implementação Python expande essa classe internamente para seus símbolos individuais. Isso não cria um novo AFN; é a mesma transição agrupada representada de forma mais detalhada para a simulação computacional.

Nas transições marcadas como `ε`, nenhum caractere da cadeia é consumido. Elas somente mudam o conjunto de estados possíveis. Nas transições rotuladas, um símbolo da entrada precisa ser consumido.
