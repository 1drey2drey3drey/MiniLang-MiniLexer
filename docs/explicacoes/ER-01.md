# ER-01 — Identificador estruturado

## 1. O que esta ER reconhece

A ER-01 define o formato dos **identificadores** da MiniLang.

Um identificador:

- precisa começar obrigatoriamente por uma letra;
- depois da primeira letra, pode continuar com letras ou dígitos;
- pode usar `_` como separador interno;
- quando `_` aparece, ele **obrigatoriamente precisa ser seguido por pelo menos um símbolo alfanumérico**;
- não pode começar por `_`;
- não pode terminar por `_`;
- não pode conter `__`.

Exemplos:

```text
a
nome
aluno1
valor_total
mediaFinal2
a1_b2
```

## 2. Definições usadas

Definimos três conjuntos auxiliares:

```text
L = letras = {A,...,Z,a,...,z}
D = dígitos = {0,...,9}
A = alfanumérico = L ∪ D
```

No código do AFNε, essas classes são expandidas para os símbolos individuais.

## 3. Linguagem reconhecida

A linguagem é formada pelas cadeias da forma:

```text
L ( A | _ A A* )*
```

A leitura correta da expressão é importante:

1. o primeiro `L` é obrigatório;
2. depois dele existe um bloco que pode repetir zero ou mais vezes;
3. em cada repetição existem duas possibilidades:
   - um único símbolo `A`;
   - `_` seguido de um bloco `A A*`, isto é, pelo menos um alfanumérico depois do `_`.

Assim, o `_` não é um caractere livre. Ele só aparece como separador de um grupo alfanumérico.

## 4. Expressão Regular formal

```text
L(A | _AA*)*
```

Também usamos:

```text
A = L | D
```

Logo, a estrutura pode ser lida como:

```text
L ( (L|D) | _ (L|D) (L|D)* )*
```

A forma anterior é preferível para explicação porque deixa visíveis as classes auxiliares.

## 5. Sintaxe exata em Python

A constante usada pelo projeto é:

```python
REGEX_ER01 = r"[A-Za-z]([A-Za-z0-9]|_[A-Za-z0-9]+)*"
```

A correspondência usada para validar uma cadeia inteira é:

```python
re.fullmatch(REGEX_ER01, cadeia)
```

### Por que `fullmatch` é importante?

`fullmatch` exige que **toda a cadeia** pertença ao padrão.

Por exemplo, a cadeia:

```text
1aluno
```

não deve ser aceita apenas porque uma parte dela poderia começar uma correspondência. O identificador só é válido quando a cadeia inteira respeita a ER.

## 6. Tradução formal → Python

| Conceito formal | Código Python |
|---|---|
| `L` | `[A-Za-z]` |
| `D` | `[0-9]` |
| `A=L∪D` | `[A-Za-z0-9]` |
| `_` | `_` |
| `A*` | `*` |
| uma ou mais ocorrências de `A` depois de `_` | `+` |
| união | `|` |
| agrupamento | `( ... )` |

O `+` da parte `_[A-Za-z0-9]+` é essencial: ele garante que um `_` nunca fique sem alfanumérico depois dele.

## 7. Explicação dos operadores

### União `|`

```text
A | _AA*
```

significa que, após a primeira letra, podemos escolher entre:

- um único alfanumérico;
- um `_` seguido de um ou mais alfanuméricos.

### Concatenação

A concatenação acontece quando os componentes aparecem em sequência.

Exemplo:

```text
_AA*
```

é:

```text
_
seguido de
A
seguido de
A*
```

### Fecho de Kleene `*`

```text
(...)*
```

permite zero ou mais repetições.

Na ER-01 isso significa que, depois da primeira letra, o identificador pode parar imediatamente ou continuar com quantos blocos permitidos forem necessários.

### Fecho positivo `+`

Na sintaxe Python:

```text
[A-Za-z0-9]+
```

significa uma ou mais ocorrências.

Isso implementa o requisito do projeto de que um `_` seja seguido por pelo menos um símbolo alfanumérico.

## 8. Exemplos aceitos e por que são aceitos

### `a`

É a menor forma válida.

```text
a
↑
L obrigatório
```

Depois da primeira letra, fazemos zero repetições do bloco externo.

### `nome`

A cadeia começa com `n` e os caracteres restantes são letras, portanto todos podem ser consumidos pela alternativa `A`.

### `aluno1`

O `1` é permitido porque `A=L∪D`.

### `valor_total`

Depois de `valor`, aparece `_`. A alternativa do `_` é escolhida e o `t` satisfaz o `A` obrigatório que vem imediatamente depois do `_`.

### `mediaFinal2`

Todos os símbolos depois da primeira letra são alfanuméricos.

### `a1_b2`

Podemos fazer:

```text
a    → primeira letra L
1    → A
_b2  → bloco _AA*
```

Portanto é aceito.

## 9. Exemplos rejeitados e por que são rejeitados

### `ε`

A cadeia vazia não possui a primeira letra obrigatória.

### `1aluno`

O primeiro símbolo é dígito, mas o primeiro elemento da ER é `L`.

### `_nome`

O primeiro símbolo é `_`; novamente falta o `L` obrigatório.

### `nome_`

O `_` foi encontrado no final, mas o bloco exige pelo menos um `A` depois dele.

### `nome__aluno`

Depois do primeiro `_`, a ER exige `A`. Outro `_` não pertence a `A`.

### `nome-aluno`

`-` não pertence à classe alfanumérica usada pela ER-01.

## 10. Casos-limite

Os casos-limite são essenciais para mostrar que a regra não aceita apenas exemplos comuns.

| Cadeia | Resultado | Por quê |
|---|---|---|
| `a` | aceita | menor identificador válido |
| `` (vazia) | rejeita | primeira letra obrigatória |
| `a_` | rejeita | `_` exige `A` depois |
| `a__b` | rejeita | `_` não pode ser seguido por `_` |
| `a1` | aceita | dígitos podem aparecer depois da letra inicial |
| `a_b` | aceita | forma mínima com separador `_` |

## 11. AFNε da ER-01

### Estrutura geral

```text
Inicial: q0
Final:   q27
Estados: 28
Transições: 35
Transições ε: 27
Transições rotuladas: 8
```

A construção usa uma versão de Thompson em que as classes `L` e `D` são rótulos agrupados na documentação e são expandidas para símbolos individuais na implementação.

### 11.1 Primeiro bloco — letra inicial

```text
q0 --L--> q1
q1 --ε--> q26
```

A transição `q0 → q1` força a primeira letra.

Essa é a parte que impede:

```text
ε
1abc
_nome
```

### 11.2 Construção de `A = L | D`

O subgrafo:

```text
q6 --ε--> q2
q6 --ε--> q4
q2 --L--> q3
q3 --ε--> q7
q4 --D--> q5
q5 --ε--> q7
```

é a união entre letra e dígito.

A partir de `q6`, o AFN pode escolher livremente o caminho de letra ou de dígito.

### 11.3 Construção do bloco `_AA*`

```text
q8 --_--> q9
q9 --ε--> q14
q14 --ε--> q10
q14 --ε--> q12
q10 --L--> q11
q11 --ε--> q15
q12 --D--> q13
q13 --ε--> q15
```

O `_` é consumido primeiro.

Depois `q14` escolhe letra ou dígito para o primeiro `A` obrigatório.

Portanto:

```text
_      → q8→q9
L/D    → bloco obrigatório seguinte
```

### 11.4 Construção de `A*`

Depois do primeiro `A`, o autômato pode entrar no ciclo:

```text
q15 --ε--> q16
q16 --ε--> q18
q16 --ε--> q17
q18 --ε--> q20
q18 --ε--> q22
q20 --L--> q21
q22 --D--> q23
q21 --ε--> q19
q23 --ε--> q19
q19 --ε--> q18
q19 --ε--> q17
```

Aqui está o efeito do `A*`:

- `q16 → q17` permite terminar;
- `q16 → q18` entra em mais uma repetição;
- `q18` escolhe letra ou dígito;
- `q19 → q18` repete;
- `q19 → q17` encerra o bloco.

### 11.5 Fechamento do bloco repetível

```text
q24 --ε--> q6
q24 --ε--> q8
q7  --ε--> q25
q17 --ε--> q25
q26 --ε--> q24
q26 --ε--> q27
q25 --ε--> q24
q25 --ε--> q27
```

Essas transições conectam o bloco à repetição externa `(A|_AA*)*` e permitem:

- repetir outro bloco;
- parar no estado final `q27`.

## 12. Exemplo de caminho de aceitação: `a1_b2`

Uma execução possível é:

```text
a  → q0 --a--> q1
ε  → q26 → q24 → q6
1  → q4 --1--> q5 → q7 → q25 → q24
_  → q8 --_--> q9
ε  → q14 → q10
b  → q10 --b--> q11 → q15 → q16 → q18
ε  → q22
2  → q22 --2--> q23 → q19 → q17 → q25
ε  → q27
```

A cadeia termina em `q27`, portanto é aceita.

O ponto principal é perceber que as transições `ε` **não consomem caracteres**. Elas apenas mudam a possibilidade de caminho do AFN.

## 13. O que acontece em `a_`

O início `a` é válido.

Depois o AFN pode escolher a alternativa do `_`:

```text
a → ... → q8
_ → q9
```

A partir de `q9`, porém, o autômato precisa chegar a um estado que consuma um `L` ou `D`.

Como a cadeia acabou, não existe símbolo alfanumérico para consumir.

Resultado: rejeita.

Isso corresponde exatamente à ER:

```text
_[A-Za-z0-9]+
```

## 14. Relação com o MiniLexer

No `src/lexer.py`, identificadores são lidos pelo método:

```python
_scan_identifier()
```

O lexer:

1. começa quando encontra uma letra;
2. avança sobre os caracteres possíveis de identificador;
3. monta o candidato inteiro;
4. executa `re.fullmatch(REGEX_ER01, candidate)`;
5. se falhar, produz `LexicalError`;
6. se passar, verifica se o lexema é uma palavra reservada.

Isso produz uma distinção importante:

```text
int
```

tem formato de identificador segundo ER-01, mas depois da validação o lexer consulta a tabela `KEYWORDS` e produz:

```text
TYPE_INT
```

Em outras palavras, **palavra reservada não substitui a ER-01**; ela é uma classificação posterior de um lexema que possui formato válido de identificador.

## 17. Limitações

A ER-01 verifica somente o **formato lexical** do identificador.

Ela não pode responder perguntas como:

```text
A variável foi declarada?
O nome já existe?
O identificador está dentro do escopo correto?
```

Essas questões pertencem a análise semântica, que está fora do escopo do MiniLexer.

## 18. Checklist mental para estudar ER-01

Lembre:

```text
1. Começa com L.
2. Depois posso usar A.
3. `_` só aparece como separador.
4. Depois de `_` preciso de pelo menos um A.
5. `__` é impossível.
6. `_` no final é impossível.
7. Primeiro dígito é impossível.
```

Pergunta típica de defesa:

> Por que `a_` é rejeitado?

Resposta essencial:

> Porque o `_` pertence ao bloco `_[A-Za-z0-9]+` e o `+` exige pelo menos um alfanumérico depois dele.

### Como ler esta tabela

Cada linha representa **uma transição agrupada da construção canônica**. Quando o símbolo é uma classe como `L`, `N`, `D` ou `C`, a implementação Python expande essa classe internamente para seus símbolos individuais. Isso não cria um novo AFN; é a mesma transição agrupada representada de forma mais detalhada para a simulação computacional.

Nas transições marcadas como `ε`, nenhum caractere da cadeia é consumido. Elas somente mudam o conjunto de estados possíveis. Nas transições rotuladas, um símbolo da entrada precisa ser consumido.
